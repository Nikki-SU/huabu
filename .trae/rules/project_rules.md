# 项目规则

## 1. CRUD 必须完整（硬性要求）

**任何可被用户管理的对象 / 字段，都必须完整实现 Create、Read、Update、Delete 四项能力。禁止只做「添加」和「编辑」就把功能称为 CRUD。**

CRUD 的本质：都是对**某一个字段的值**的改变。

- **Create**：为字段写入初始值。
- **Read**：把字段的当前值呈现出来（图例、页签、画布、列表等）。
- **Update**：改写该字段的值，并立即反映到所有读取它的地方。
- **Delete**：让该字段的值失效 / 移除该记录——必须真的生效、真的落盘。

### 必须遵守的细则

1. **删除必须真实可用**：不允许出现「按钮可见但点不动」「按钮被 `visibility:hidden` / `disabled` 藏起来」「删了没反应」「刷新后又回来」这类假删除。
2. **禁止「内置 / builtin 不可删除」式拦截**：内置对象和用户自建对象享有同等的删除权。若确有保护需求，只能是「至少保留一项」这类业务底线，并且必须给出明确提示，不能静默失败。
3. **删除必须持久化**：删除结果要写进持久化数据（本项目为 OPFS 的 `huabu-workspace.json`，v4），刷新、重开浏览器后保持删除状态。禁止在加载时无条件重建已被删除的默认项。
4. **删除必须级联处理，但不得污染其他对象**：被删对象在别处的引用要一并修正（节点被删 → 相关连线一并删除），不允许留下悬空引用。对于「属性」这类上层对象，其下的实例必须显式收敛到保留属性「未分类」——既不许留成悬空的旧 `type`，也**绝不许改写成任意其他用户属性**。详见 §3。
5. **删除的记录方式要显式**：内置项被删后要留有可序列化的删除标记（如 `deletedBuiltins`），而不是依赖「恰好没被重建」。
6. **字段级一致性**：新增一个字段时，同时检查它的增、查、改、删四条路径是否齐全；少任何一条都算功能未完成。
7. **交付前自检**：新增 / 修改任何可管理对象后，必须实际走一遍「创建 → 修改 → 删除 → 刷新页面确认仍已删除」，并在浏览器中验证，不得只靠读代码判断。

## 2. 项目既有约定（继续有效）

- 每次改动后自动提交并推送到 `Nikki-SU/huabu` 的 `main` 分支。
- 持久化只用 File System Access API / OPFS，不使用 localStorage。
- UI 只用图标，不使用文字按钮标签；简洁优先。
- 父子 = **part-of 森林**（组成关系，不是 is-a 继承）：一个理论由多个小点组成、一个事件有多个面向、一个概念衍生出若干东西。一卡一父，单归属，因此无环、路径唯一、可整支折叠与平移。父子挂在**卡片定义层**（`S.cardTrash[*].parent`），实例层用节点 `parent` 指向同一文档内的父**实例**。父子与连线是**两条正交轴**：父子管归属与打包，连线管关系，分表存储，互不覆盖。
- 小点必须是真实卡片/实例，既要能单独检索，也要在检索父节点时被递归带出。
- 图片属于卡片内容而非一种类型，需支持复用、剪贴板粘贴、拖拽上传，且不进入搜索。
- 字体必须内嵌（LXGW 文楷 97 个子集），任何设备都不能退化成宋体。

## 3. 三层模型与删除语义（硬性要求）

对象层级：

- **属性**：逻辑、事件、理论等大类。出现在左上角图例与左栏 tab 行。
- **卡片 / 类型**：某个属性下的一种内容组合，在组件库里显示为一张卡片，可以有多个实例。
- **实例**：某张卡片在某张图上的画面，即画布上的一个节点。

1. **三级别各有删除入口，互不等价**：
   - 画布节点双击 / 右键删除 → 只删这一个**实例**。
   - 左栏卡片双击、卡片右上角垃圾桶 → 删除整张**卡片**：它在**所有文档**中的实例与连线一并删除，卡片进入被删除库。
   - 图例 / tab 右键 → 删除**属性**（允许有实例）。
2. **删除属性不得污染**：属性被删时，其下实例与被删卡片一律转为保留属性「未分类」（`uncat`），绝不留成悬空 `type`，也绝不改成别的用户属性。「未分类」不可删除、不可改名，只在需要时出现在 tab 行。
3. **「未分类」可再赋属性**：节点上的标签按钮或库条目右键可把实例改回任意存活属性。
4. **被删除库是左栏搜索框下方的独立 tab**（`S.libTab === '__trash__'`，单独一行，位于属性 tab 之上），收录「被删卡片」与「被删属性」两栏，按属性分组并支持搜索：
   - **单击 = 恢复**，**双击 = 彻底删除**（连同残留实例、连线、`S.cardTrash` 记录）。
   - 不设恢复按钮、不做强确认弹窗。
5. **卡片身份 = 标题 | 属性**（`cardKey = title+'|'+normTypeId(type)`），**`S.cardTrash` 是唯一的全量卡片定义表，记录常驻**；`deleted` 是唯一的状态位，只表示「是否进被删除库」：
   - **有实例**：表里有记录（除非 `auto:1` 空壳且已失去最后一个实例，才由 `gcCard` 回收），渲染在画布与库中。
   - **零实例、`deleted:false`**：记录照常住在它自己的属性 tab 里，正常颜色，单击即新建实例。
   - **已进被删除库、`deleted:true`**：同一条记录，类别与内容原封不动，**仍然住在它自己的属性 tab 里，只是用更浅的颜色（属性色混白 + 虚线边）渲染**，同时出现在被删除库中；在被删除库里单击 = 恢复（只把 `deleted` 置回 `false`），双击 = 彻底删除。
   - 恢复出来的卡片与普通卡片**完全同构**：不得为它发明任何特殊标记、特殊数组或特殊状态。它只是「暂时没有实例」而已。
   - 只有彻底删除（`purgeCard`，删掉表里那条记录）才会让卡片真正消失。
   - 判定「最后一个实例被删」只能数 `S.docs[].nodes` 里的实例（`nodeInstanceCount`），绝不能把卡片表本身算进去。
   - **同一卡片不可改标题 / 改属性**：标题或属性一变就是**另一张卡片**（两张，不是一张的 diff）。**尺寸、位置不算实质**，永远不构成 diff。
   - **diff 只允许在「内容」与「图片」两个字段上**：偏离记在实例的 `ov` 上，有效值仍是节点自身的 `text`/`img`；偏离数用 `devCount` 显示为角标。接收方式只有三向且**永不做三方合并**：单击角标 = 拉（放弃覆写、接收母版），右键角标 = 推（把本实例写回母版并 `propagateCard` 同步所有同卡实例）。
6. **每月清理**：每次载入时若本月尚未清理（`S.lastGc` 记月份），清除「建立于六个月及以前」且「无任何实例」或「实例均无任何连线」的属性，连同其残留实例、被删卡片一起清掉。
7. **改名 / 改色即全量同步**：属性改名，其下所有实例标题与被删卡片标题同步改名；改色由 `typeColor(id)` 派生，天然同步所有读取处。
8. **持久化**：`S.cardTrash`（**唯一卡片表**，不是额外仓库）必须写入 `huabu-workspace.json`（工作区全量 v4；单文档 `serialize` v3，只带本文档节点引用到的卡片）并在恢复时读回。载入收敛规则：
   - 死属性上的记录改到 `uncat`；按当前 `标题|属性` 重算 key；
   - **不得**清掉「已有活实例」的卡片记录——记录必须常驻；
   - 节点 `parent` 或卡片 `parent` 指向不存在的对象 ⇒ 置空（提升为根），绝不留悬空引用；
   - 一卡一父（重复归属只留第一个）；`auto:1` 空壳卡失去最后一个实例即回收。
   `S.libTab` 允许取保留值 `'__trash__'`。

9. **整包复刻（part-of 存在的意义）**：从库里的卡片复刻时，用 `cardDescendantKeys` 把整支一起复制，**保留包内父子链**，并给每个新实例写 `prov = 源根卡片标题`，画布上渲染为「来自 X」血缘；血缘只做展示，源被删不级联。**默认局部（分叉）**，绝不自动回灌母版；回灌必须显式（推 = `pushCard`）。
10. **递归检索**：命中父 ⇒ 向下整支带出，子项前加 `↳ 祖先 / 路径` 面包屑；命中子 ⇒ 自身结果带完整祖先路径。
